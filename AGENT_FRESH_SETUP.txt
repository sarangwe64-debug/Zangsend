STEP 1 — SECRETS FILE (user provides once; agent creates from template)
================================================================================
Copy .setup-secrets.local.example → .setup-secrets.local (gitignored).
Fill values from user OR from existing .env if present on disk.

Required keys:
  VITE_SUPABASE_URL          → Supabase Dashboard → Settings → API → Project URL
  VITE_SUPABASE_ANON_KEY     → same page → anon public key
  SUPABASE_ACCESS_TOKEN      → https://supabase.com/dashboard/account/tokens (sbp_...)
  SUPABASE_PROJECT_ID        → xhwpiagznwkoroitoulz (ref from URL)
  APIFY_TOKEN                → Apify console → Integrations
  APIFY_TOKEN2               → optional fallback Apify token
  TELEGRAM_BOT_TOKEN         → @BotFather on Telegram
  GITHUB_TOKEN               → https://github.com/settings/tokens (repo, workflow scopes)
  NETLIFY_AUTH_TOKEN         → https://app.netlify.com/user/applications#personal-access-tokens

Load secrets in PowerShell before any command:
  $f = ".setup-secrets.local"
  if (-not (Test-Path $f)) { $f = ".env" }
  Get-Content $f | ForEach-Object {
    if ($_ -match '^\s*([^#][^=]+)=(.*)$') {
      Set-Item -Path "env:$($matches[1].Trim())" -Value $matches[2].Trim()
    }
  }
  $env:GH_TOKEN = $env:GITHUB_TOKEN
  $env:SUPABASE_ACCESS_TOKEN = $env:SUPABASE_ACCESS_TOKEN
  $env:NETLIFY_AUTH_TOKEN = $env:NETLIFY_AUTH_TOKEN

STEP 3 — SUPABASE (cloud backend)
================================================================================
  npx supabase link --project-ref $env:SUPABASE_PROJECT_ID

  npx supabase secrets set `
    "APIFY_TOKEN=$env:APIFY_TOKEN" `
    "APIFY_TOKEN2=$env:APIFY_TOKEN2" `
    "TELEGRAM_BOT_TOKEN=$env:TELEGRAM_BOT_TOKEN" `
    --project-ref $env:SUPABASE_PROJECT_ID

  Deploy all edge functions:
    $ref = $env:SUPABASE_PROJECT_ID
    foreach ($fn in @("find-email","send-email","create-draft","process-queue","telegram-bot")) {
      npx supabase functions deploy $fn --project-ref $ref
    }

  Verify process-queue (expect HTTP 200):
    $h = @{ Authorization = "Bearer $env:VITE_SUPABASE_ANON_KEY"; "Content-Type" = "application/json" }
    Invoke-WebRequest -Uri "$env:VITE_SUPABASE_URL/functions/v1/process-queue" `
      -Method POST -Headers $h -Body '{}' -UseBasicParsing

  Database schema: supabase/schema.sql (apply via Supabase SQL editor if tables missing).

STEP 5 — NETLIFY (frontend hosting)
================================================================================

    (then same env:set and deploy steps as Option A)

  Build config: netlify.toml (npm run build, publish dist, Node 20)
  SPA redirects: public/_redirects (/* /index.html 200)

  Link GitHub for auto-deploy (preferred: fully automated via API):

       - netlify api createDeployKey → add public_key to GitHub repo deploy keys (gh api)

         (provider github, repo sarangwe64-debug/Zangsend, repo_id, branch master,
          cmd npm run build, dir dist, deploy_key_id)
       - POST GitHub webhook to https://api.netlify.com/hooks/github (push, pull_request)
    B) UI fallback: Netlify → Build & deploy → Link repository → Zangsend / master

TROUBLESHOOTING

  GitHub deploy failed   → SUPABASE_ACCESS_TOKEN or SUPABASE_PROJECT_ID missing in gh secrets
  Netlify blank/broken   → VITE_* env vars missing; rebuild after env:set
  Login fails on Netlify → Step 6 Auth URL configuration

  Build TS errors        → run npm run build and fix before deploy
